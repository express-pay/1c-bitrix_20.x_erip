# Расширение 1C-Битрикс 20.x  сервиса «Экспресс Платежи: ЕРИП»
<p>Расширение CMS 1C-Битрикс для интеграции с сервисом «Экспресс Платежи». Расширение позволяет выставить счет в системе ЕРИП, получить и обработать уведомление о платеже в системе ЕРИП.</p>

<a href="https://express-pay.by/extensions/1c-bitrix/erip">Инструкция для установки и настройки</a>

<a href="https://www.youtube.com/c/express-pay-by">Наш Youtube канал с опубликованными видео по расширениям</a>

Версия: 1.1.2

## Описание

Обработчик платежной системы для 1С-Битрикс (модуль sale), интегрирующий оплату через сервис «Экспресс Платежи» по схеме ЕРИП.
При инициации оплаты формирует параметры счета и отправляет запрос на API «Экспресс Платежи» (`/v1/web_invoices`) для выставления счета. После выставления счёта выводит страницу с инструкцией оплаты в ЕРИП и, при необходимости, QR‑кодом.
Уведомления об оплате принимаются через стандартный обработчик 1С‑Битрикс `sale_ps_result.php` (значение по умолчанию подставляется в поле `ERIP_NOTIFICATION_URL`).

## Возможности

- Работа с боевым и тестовым API (переключатель `ERIP_IS_TEST_API`; используется `https://api.express-pay.by/v1/` или `https://sandbox-api.express-pay.by/v1/`).
- Выставление счёта через API `web_invoices` с передачей ServiceId, номера заказа (AccountNo), суммы (Amount) и служебных URL возврата (ReturnUrl/FailUrl). Оба URL ведут на `https://<server_name>/bitrix/tools/sale_ps_result.php` с параметром `result=success` или `result=fail`.
- Формирование цифровой подписи запросов (HMAC-SHA1, результат в верхнем регистре) на основе токена и параметров запроса; секретное слово задаётся в настройках (`ERIP_SECRET_WORD`).
- Отображение инструкции оплаты в ЕРИП с путём ветки услуги (`ERIP_ERIP_PATH`), номером заказа и суммой.
- Вывод QR‑кода для оплаты (`ERIP_IS_SHOW_QR_CODE`), полученного через API `qrcode/getqrcode` (возвращается Base64-изображение).
- Настройки редактируемости данных плательщика в ЕРИП: ФИО (`ERIP_IS_NAME_EDITABLE`), адрес (`ERIP_IS_ADDRESS_EDITABLE`), сумма (`ERIP_IS_AMOUNT_EDITABLE`).
- Обработка уведомлений об оплате (POST-параметры `Data` и `Signature`), установка статуса оплаты при событиях с `CmdType = 3` и статусом `3` или `6`.
- Обязательная проверка цифровой подписи всех уведомлений секретным словом `ERIP_SECRET_WORD_FROM_NOTIFICATION`. Уведомления без подписи или с неверной подписью отклоняются.
- Защита от подделки и повторов: номер счёта (`AccountNo`) и сумма из уведомления сверяются с платежом, уже оплаченный платёж повторно не проводится.

## Требования

- 1С-Битрикс версии 20.x и выше с модулем «Интернет-магазин» (sale) и стандартной точкой приёма результатов оплаты `sale_ps_result.php`.
- PHP 7.1 и выше.
- Заполненное поле «URL сайта» (`server_name`) в настройках Главного модуля. Из него формируются адрес уведомлений и адреса возврата покупателя; если поле не заполнено, счёт не будет выставлен.
- Исходящий доступ с сервера к доменам API «Экспресс Платежи»: `api.express-pay.by` (production) и/или `sandbox-api.express-pay.by` (test).
- Значения из личного кабинета «Экспресс Платежи»: токен (`ERIP_TOKEN`), номер услуги (`ERIP_SERVICE_ID`), секретные слова (`ERIP_SECRET_WORD` и `ERIP_SECRET_WORD_FROM_NOTIFICATION`), путь ветки ЕРИП (`ERIP_ERIP_PATH`).
- Публично доступный по https URL для приёма уведомлений об оплате (`ERIP_NOTIFICATION_URL`).

## Установка

Обработчик устанавливается вручную, без Маркетплейса. Код тот же, что и в модуле Маркетплейса `triincom.expresspayerip`.

1. Скопируйте папку `install/expresspay_erip/` из репозитория на сайт в каталог пользовательских обработчиков платёжных систем, сохранив имя папки `expresspay_erip`:
   - `/local/php_interface/include/sale_payment/expresspay_erip/` (рекомендуется)
   - или `/bitrix/php_interface/include/sale_payment/expresspay_erip/`

   В папке должны оказаться `handler.php`, `.description.php`, `lang/` и `template/`.
2. Файлы обработчика в кодировке UTF-8. Если сайт работает в кодировке windows-1251, перекодируйте файлы из `lang/` и `template/lang/` в windows-1251.
3. Проверьте, что в настройках Главного модуля заполнено поле «URL сайта» (`server_name`).
4. В административной части откройте «Магазин → Настройки → Платёжные системы», добавьте новую платёжную систему и выберите обработчик «Экспресс Платежи - ЕРИП» (`expresspay_erip`).
5. Заполните параметры обработчика (см. «Настройка»).
6. Укажите в личном кабинете «Экспресс Платежи» адрес для уведомлений значением `ERIP_NOTIFICATION_URL` и включите цифровую подпись уведомлений с тем же секретным словом, что и в `ERIP_SECRET_WORD_FROM_NOTIFICATION`.

Проверка установки: обработчик появляется в списке доступных обработчиков платёжных систем и позволяет сохранить настройки.

## Настройка

Настройка выполняется в параметрах созданной платёжной системы. Поля, используемые обработчиком:

- `ERIP_IS_TEST_API` — работа в тестовом режиме (Y/N).
- `ERIP_TOKEN` — API-ключ (токен) доступа к API.
- `ERIP_SERVICE_ID` — номер услуги в сервисе «Экспресс Платежи».
- `ERIP_IS_SHOW_QR_CODE` — показывать QR‑код (Y/N).
- `ERIP_SECRET_WORD` — секретное слово для цифровой подписи запросов.
- `ERIP_NOTIFICATION_URL` — адрес для получения уведомлений. По умолчанию подставляется `https://<server_name>/bitrix/tools/sale_ps_result.php`; если «URL сайта» в Главном модуле не заполнен, поле остаётся пустым и его нужно заполнить вручную. Если сохранённый адрес указывает на другой домен, в настройках выводится предупреждение.
- `ERIP_IS_USE_SIGNATURE_FROM_NOTIFICATION` — использовать цифровую подпись уведомлений (Y/N, по умолчанию `Y`). Подпись проверяется всегда, независимо от этой настройки; при значении `N` в настройках выводится предупреждение.
- `ERIP_SECRET_WORD_FROM_NOTIFICATION` — секретное слово для подписи уведомлений. **Обязательно**: без него уведомления об оплате отклоняются и оплата не засчитывается.
- `ERIP_ERIP_PATH` — путь ветки ЕРИП услуги.
- `ERIP_IS_NAME_EDITABLE` — разрешено изменять ФИО плательщика (Y/N).
- `ERIP_IS_ADDRESS_EDITABLE` — разрешено изменять адрес плательщика (Y/N).
- `ERIP_IS_AMOUNT_EDITABLE` — разрешено изменять сумму оплаты (Y/N). Если плательщик изменит сумму, уведомление с суммой, не совпадающей с суммой платежа, будет отклонено.

Пример значений (без секретов):

- `ERIP_IS_TEST_API`: `Y`
- `ERIP_TOKEN`: `YOUR_API_TOKEN`
- `ERIP_SERVICE_ID`: `12345`
- `ERIP_SECRET_WORD`: `YOUR_SECRET_WORD`
- `ERIP_NOTIFICATION_URL`: `https://example.by/bitrix/tools/sale_ps_result.php`
- `ERIP_SECRET_WORD_FROM_NOTIFICATION`: `YOUR_NOTIFICATION_SECRET_WORD`
- `ERIP_ERIP_PATH`: `Интернет-магазины/сервисы->[Первая буква сайта]->[Имя сайта]`

## Использование

1. Покупатель оформляет заказ и выбирает способ оплаты «Экспресс Платежи - ЕРИП».
2. 1С‑Битрикс вызывает обработчик, который выставляет счёт через API (`web_invoices`) и показывает страницу с инструкцией оплаты в ЕРИП (путь `ERIP_ERIP_PATH`, номер заказа, сумма).
3. После оплаты в ЕРИП сервис «Экспресс Платежи» отправляет уведомление на `ERIP_NOTIFICATION_URL` (обработчик `sale_ps_result.php`).
4. Обработчик проверяет подпись уведомления. Если `CmdType = 3` и `Status = 3` или `Status = 6`, он сверяет номер счёта и сумму с платежом и, если всё совпадает, устанавливает статус оплаты.

Проверка оплаты:

- Тестовый режим (sandbox): включите `ERIP_IS_TEST_API = Y` и используйте тестовые значения токена/услуги; запросы будут выполняться к `sandbox-api.express-pay.by`.
- Имитация уведомления (проверка обработчика): отправьте POST-запрос на `ERIP_NOTIFICATION_URL` с полями `Data` и `Signature`. `AccountNo` должен быть ID существующего неоплаченного платежа, а `Amount` — равен сумме этого платежа, иначе уведомление будет отклонено. Пример `Data` (JSON):

```json
{"CmdType":3,"Status":3,"AccountNo":100,"Amount":"10.00","Payer":"Иванов Иван"}
```

Поле `Signature` должно быть равно `UPPERCASE(HMAC-SHA1(Data, ERIP_SECRET_WORD_FROM_NOTIFICATION))`, где `Data` — исходная JSON-строка уведомления (регистр подписи при проверке не учитывается).
